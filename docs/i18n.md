# Languages

Deskway is available in English (`en`), Simplified Chinese (`zh-Hans`) and Traditional Chinese
(`zh-Hant`, using Taiwan wording). Any text missing from a catalog falls back to English.

## Host: choosing the language

- By default the host follows the system UI language. Any `zh-TW`, `zh-HK`, `zh-MO` or
  `zh-Hant*` locale selects `zh-Hant`; any other `zh*` locale (`zh-CN`, `zh-SG`, `zh`,
  `zh-Hans*`) selects `zh-Hans`; everything else selects `en`.
- The host has its own language setting, independent of the browser controlling it. Notices
  shown on the controlled computer ("{name} is controlling this computer", "Received 2 files")
  use the host's language, because they are meant for the person sitting at that computer.
- The host stores its choice as `lang` in its config file (`host.json`): `"en"`, `"zh-Hans"` or
  `"zh-Hant"`, or no value to follow the system. It is set from the Language row in the panel or
  from the installer's first screen. When the Windows service is installed, the copy in
  `C:\ProgramData\Deskway` is the one that takes effect, and the panel changes it through the
  service pipe.
- Windows service names and descriptions remain in English in every language ("Deskway
  Network", "Deskway Agent").
- The web controller has its own language choice, which defaults to the browser's language. The
  same mapping and the glossary below keep the two sides consistent. The panel's QR code help
  refers to the web buttons as “Add” / 「添加」 / 「新增」 and “Request control” / 「请求控制」 /
  「請求控制」.

## Host: catalogs

The host's texts are in `host/i18n/en.json`, `zh-Hans.json` and `zh-Hant.json`, flat JSON
objects with dotted keys (`panel.autostart`, `err.no_admin`, `note.received.other` and so on).

- All three files have exactly the same keys, and each key has the same `{placeholders}` in
  every language. `tests/unit/i18n.test.mjs` checks both.
- Placeholders are written `{name}` and filled by `tf(key, &[("name", value)])` in Rust and by
  `t(key, { name })` in pages.
- Counts follow the web client's plural convention (`key.one` and `key.other`), so both sides use
  the same one. They are filled by `tn(key, n, …)` with `{n}`. In Chinese both keys have the
  same text.
- Language names (`lang.en`, `lang.zh-Hans`, `lang.zh-Hant`) are each written in their own
  language and are identical in every catalog.
- User-visible Chinese text appears only in the catalogs. `tests/unit/i18n.test.mjs` scans
  `host/src` (all platforms, excluding test modules) for Chinese in string literals and page
  text. Comments are written in English.
- Pages (`panel.html`, `setup.html`, `overlay.html`) mark text with `data-i18n="key"` and
  attributes with `data-i18n-attr="aria-label=key,placeholder=key"`. The host injects
  `window.I18N = { lang, dict }` before the page script runs and calls `setLang(...)` when the
  language changes.

## Voice

Texts are short and plain, in sentence case: "Start with Windows", "Lock when disconnected",
"Add a device", "Open folder", "Disconnect". Chinese texts keep the tone of the
existing ones. Quotation marks are 「」 in both Chinese variants and “ ” in English.

UI instructions describe the action to take. Use “device” for the device the person controls
from and “computer” for the computer they control. Default device names can include a device
type.

## Web

This section covers the browser client (`web/static`).

### Catalogs

- The texts are in `web/static/i18n/en.json`, `zh-Hans.json` and `zh-Hant.json`, each a single
  flat JSON object. Keys are dotted and grouped by area: `login.*`, `wait.*` (a new device
  waiting for approval), `approve.*`, `list.*`, `detail.*`, `display.*`, `devices.*` (the
  **My devices** page), `members.*` (**Members**), `setup.*` (account setup and recovery),
  `computer.*`, `pw.*`, `tb.*` (the session toolbar),
  `session.*`, `route.*`, `kb.*` (the on-screen keyboard), `pad.*` (the mouse panel), `clip.*`,
  `xfer.*` (transfers), `pair.*`, `err.*`, `common.*` and so on.
- Placeholders are written `{name}` and filled by `t(key, { name })`. Every language has the same
  keys, and each key has the same placeholders.
- Plurals: a key used with a number `n` has a `key.one` and a `key.other` form, and English picks
  between them with `Intl.PluralRules`. Chinese has no plural forms, so both keys carry the same
  text; they exist only to keep the key sets identical.
- `lang.en`, `lang.zh-Hans` and `lang.zh-Hant` give each language's name in that language
  (English, 简体中文, 繁體中文) and are identical in every catalog. Do not translate them.
- A key missing from a catalog shows the English text. A key missing from the English catalog as
  well shows the key itself.
- Codes from the server or the computer (`pair.<code>`, `xfer.why.<code>`) map to keys. A code
  without a key, and any raw error message, is shown as a general message instead.
- Names that people chose (computers, devices, display names) are never translated. A new
  device's default name (`device.*`, for example "Windows PC") is generated in the language in
  use when the device is added.

### Choosing the language

1. A choice made in this browser, stored in `localStorage['deskway.lang']` (`en`, `zh-Hans` or
   `zh-Hant`).
2. Otherwise, `navigator.languages` in order: `zh-TW`, `zh-HK`, `zh-MO` or any `zh-Hant*` selects
   Traditional Chinese; any other `zh*` selects Simplified Chinese; the first language of any
   other kind selects English.
3. Otherwise, English.

Nothing is stored until the person picks a language. The choice belongs to the browser, not to
the account, and the server does not know about it.

Only the chosen catalog and the English catalog are fetched, before the first screen is drawn.
`<html lang>` follows the language, and dates and times are formatted with `Intl` using `en`,
`zh-CN` or `zh-TW`.

The language switchers are at the top right of the sign-in page and at the end of the
**My devices** page, with each language shown in its own name. Switching redraws the page
immediately, without a reload. The switchers are not available during a session, which is never
reloaded or redrawn because of a language change.

### Writing texts

- The JS modules (`js/**`), `index.html` and `style.css` contain no user-visible text. Any words
  that CSS displays come from the page (`content: attr(data-…)`). Comments are written in
  English.
- Keep English short where space is limited: the toolbar (two rows below 860 px wide), the
  keyboard bar, the clipboard panel and ball menu, dialogs, and the transfer card (one line, at
  most about 360 px). A toolbar label that is still too long wraps to a second line.
- Key caps on the on-screen keyboard are labelled as on a real keyboard (`Esc`, `F1`, `Ctrl`,
  `Win`, `Alt`, `Shift`, `Tab`, `Caps`, `Enter`, arrows, ⌘, ⌥). Only Space and the spoken key
  names (`kb.key.*`) are translated.
- Quotation marks: English uses “ ” and ’; Chinese uses 「」 and full-width punctuation.

### Checks

- `node --test tests/unit/i18n.test.mjs` is the single checker for both the web client and the
  host. It checks that each side's three catalogs have identical keys and placeholders, that keys
  are dotted, that `.one`/`.other` pairs are complete and that the English catalog contains no
  Chinese. It also checks that there is no Chinese outside comments in the JS modules (`js/**`),
  `index.html`, `style.css`, and the host's Rust sources and pages on every platform (excluding
  test modules).
- `tests/e2e/i18n.test.mjs` and `layout.test.mjs` (run by `tests/e2e/run.mjs`) check the
  language chosen on a first visit, the switchers, every main screen in each language (no raw
  keys, no text in another script), and the English layout at 390, 768 and 1440 px wide. All
  other end-to-end checks run in English, which is set before each page loads, and read the text
  they expect from the catalogs (`t`, `q` and `fixed` in `tests/e2e/harness.mjs`), never from
  strings written into the test.
